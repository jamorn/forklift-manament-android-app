# 13 — ปัญหาการทำงานข้ามวันของกะดึก (Overnight / Night Shift)

> เอกสารนี้บันทึกปัญหาที่ค้นพบจากการวิเคราะห์การทำงานของกะดึก (N: 22:00–06:00)
> ที่คาบเกี่ยว 2 วันปฏิทิน และแนวทางที่ตกลงกันว่าจะแก้ไขอย่างไร
>
> **สถานะ:** 📝 ยังไม่แก้ไข — บันทึกแนวทางเพื่อเป็น reference ก่อนลงมือ

---

## 1. บริบทการทำงานของกะดึก (8 ชั่วโมง คาบ 2 วัน)

กะดึก (Night shift, กะ N) ทำงาน 8 ชั่วโมง ตั้งแต่ **22:00 – 06:00**
ซึ่งคาบเกี่ยว **2 วันปฏิทิน**:

```
22:00 ────────────────────────────── 06:00
├── 22:00 – 23:59  (2 ชม.)  ── เป็นของวันเริ่มกะ (เช่น 02 ส.ค.) ──┤
└── 00:00 – 05:59  (6 ชม.)  ── หลังเที่ยงคืน (03 ส.ค.) ────────────┘
```

| วันปฏิทิน        | ช่วงเวลา      | ชั่วโมง |
|-----------------|---------------|--------|
| วันเริ่มกะ (02) | 22:00 – 23:59 | 2 ชม.  |
| วันที่ 2 (03)   | 00:00 – 05:59 | 6 ชม.  |

รวม **8 ชั่วโมง** แต่คาบ **2 วัน** ตามปฏิทิน

---

## 2. กฎการทำงาน (Business Rule) — ตรวจ 1 ครั้งต่อกะ

- **1 กะ ตรวจรถ 1 ครั้ง** (M / E / N)
- ดังนั้น **1 วันทำงาน (work day) ตรวจ 3 ครั้ง** (ห่างกันตามกะ)
- แต่ละกะตรวจรถ **ชุดเดียวกัน** (ทุกคันในแผนกที่รับผิดชอบ)
- แต่ละกะตรวจเสร็จ → บันทึกเป็น **เอกสาร (Doc) ของกะนั้น** แยกจากกัน

---

## 3. ระดับการจัดเก็บ: แยก Doc ต่อกะ (แยกกะใครกะมัน) ✅

**ข้อสรุป: ควรแยก Doc ต่อกะ** ไม่ใช่รวมทุกกะเข้า doc วันเดียว
โดยแยกตาม **"work date + กะ"** เป็น 3 docs ต่อวันทำงาน:

```
work-day (02 ส.ค.)
├── doc: checksheet กะ M  (06:00 – 14:00)   → main_remark ของกะ M
├── doc: checksheet กะ E  (14:00 – 22:00)   → main_remark ของกะ E
└── doc: checksheet กะ N  (22:00 – 06:00)   → main_remark ของกะ N  (ข้ามวัน → เป็นของงานของวัน 02)
```

### 3.1 เหตุผลสำคัญ — แยกความรับผิดชอบ / ไล่บี้ผู้ทำ

ตัวอย่างสถานการณ์จริง:
> กะดึกทำ "แก้วแตก" ที่รถ แล้ว**ไม่บอก/เก็บเงียบ**
> กะเช้ามารับงานต่อ เดินไปเห็น "แก้วแตก" → สังเกตได้ว่า**ไม่ใช่เหตุการณ์ที่เกิดในกะตัวเอง**
> operator จึงบอกหัวหน้าได้ก่อนว่า *"ผมเจอแก้วแตก แต่ไม่ใช่ในกะเรานะ"*
> ทำให้หัวหน้าไปไล่บี้หาคนทำ (กะก่อนหน้า) ได้

**ข้อสรุป:** ต้องสามารถระบุได้ว่า **เหตุการณ์/ความผิดปกติที่พบ เกิดในกะใด** (หน่วยงานไหนเป็นผู้ทำ/ผู้พบ)
→ จึงต้อง **แยกข้อมูล/เอกสารเป็นรายกะ ไม่ใช่รวมเป็น doc วันเดียว**

### 3.2 เหตุผลที่แยก (เปรียบเทียบรวม doc กับแยก doc)

| พิจารณา | รวม doc วันเดียว | แยก doc ต่อกะ |
|---------|------------------|---------------|
| รู้ว่ากะไหนพบเหตุการณ์ (แก้วแตก) | ต้องมี field ระบุกะ/เวลาในรายการเพื่อ filter | ✅ แยกเป็นเอกสาร รู้ทันทีว่ากะไหน |
| operator บอกหัวหน้า "ไม่ใช่กะเรา" | ต้อง cmp ข้ามกะ | ✅ เห็นทีละกะชัดเจน |
| ทุกกะตรวจชุดเดียวกัน → เขียนทับกัน | เสี่ยง | ✅ ไม่แย่งกัน |
| ตรวจครบ "1 ครั้ง/กะ/คัน" | ทั้งวัน 3 ครั้ง/คัน ปนกัน | ✅ แยก 3 ชุดตรวจชัดเจน |

## 4. ใช้ `main_remark` (ใกล้ manhour meter) เป็นตัวบอกเหตุการณ์ในเอกสาร ✅

ใน form checklist มีช่อง **`mainRemark` (หมายเหตุรวม)** ที่อยู่**ใกล้กับ manhour meter**
ระบบมีช่องนี้อยู่แล้ว ทั้งใน UI (`ChecklistUiState.mainRemark`) และใน model (`DailyChecksheet.main_remark`)

### 4.1 บทบาทของ `main_remark` กับประเด็น "แยกกะ"
- operator ใช้ช่อง `main_remark` **บันทึกเหตุการณ์/สภาพผิดปกติ** ที่พบในกะของตน
  เช่น *"พบกระจก/แก้วแตก ที่ FL-เลขที่ ... กะเช้า"*
- ช่องนี้ถูกเก็บลง **doc ของกะนั้น** → ระบุ **กะ + ข้อความ** ได้ว่าเป็นของกะไหน
- ใช้เป็นหลักฐานให้หัวหน้าไล่บี้หาคนทำได้

### 4.2 ระบบมี "Copy-Forward" (pre-fill จากกะก่อน) อยู่แล้ว
พบที่ `ChecklistViewModel` บรรทัด ~104-111:
```kotlin
// Copy-Forward: pre-fill results + remarks + meter จากกะก่อน
... copy(cs.remarks)
... mainRemark = cs.main_remark,
... meter = ...
```
หมายถึง ระบบ pre-fill `main_remark` จากกะก่อนมาให้ → operator เห็นหมายเหตุของกะก่อน
> 💡 **ต้องระวัง:** อย่าให้ copy-forward ทำให้แยกกะไม่ออกว่า "ใครเขียนตอนไหน"
> ข้อเสนอ: ถ้าใช้ copy-forward ควร **เก็บที่มา** ของ `main_remark` ไว้ (เช่น กะ/เวลาที่เขียน)
> หรือ **append แทน overwrite** เพื่อไม่ให้ "เป็นของกะไหนเขียน" มืด

### 4.3 field ของ `DailyChecksheet` (ปัจจุบัน)

## 5. ปัญหาที่ค้นพบ

### 5.1 สถานการณ์ทำงานจริง
Operator กะดึก **ลืมตรวจรถ ช่วง 22:00–23:59** แล้วไปตรวจต่อ **หลังเที่ยงคืน (00:01)** ซึ่ง
**ในงานจริงเขามีสิทธิทำได้** เพราะยังอยู่ในช่วงเวลากะของเขา (ยังไม่ถึง 06:00)

### 5.2 ความผิดปกติของระบบปัจจุบัน
ปัจจุบันระบบใช้ `LocalDate.now()` (วันตามปฏิทิน) เป็น key ในการแยกข้อมูล:

| สถานการณ์ | ระบบทำอย่างไรตอนนี้ | ผลกระทบ |
|-----------|--------------------|---------|
| ตรวจบางคันก่อนเที่ยงคืน แล้วตรวจต่อหลังเที่ยงคืน | พอเที่ยงคืน `todayStr` เปลี่ยนเป็นวันใหม่ → `remember` โหลดใหม่ แสดงเฉพาะรถที่ตรวจของวันใหม่ → คันที่ตรวจแล้วก่อนเที่ยงคืน**หาย / ขึ้น "รอตรวจ" อีก** | ❌ Operator สับสน กดซ้ำได้ ตรวจครบผิด |
| ตรวจหลังเที่ยงคืนคันสุดท้าย แล้วกด submit | `DailyChecksheet.shift = N` แต่ `date` ใช้ `LocalDate.now()` = วันที่ 2 (03) | ❌ วันที่บันทึกไม่ตรงกับวันเริ่มกะ |

**แก่นของปัญหา:** ระบบตัดวันที่ที่ **เที่ยงคืนตามปฏิทิน (00:00)** แทนที่จะตัดที่ **สิ้นสุดกะ (06:00)**

## 6. แนวคิดที่ตกลงกัน (Rule ใหม่)

> **การตรวจที่เกิดขึ้นหลังเที่ยงคืน แต่ก่อน 06:00 (เย็น 6 โมงเช้า)**
> ให้ถือว่าเป็น **ของวันก่อนหน้า (วันเริ่มกะ)** เพราะมันยังเป็นกะของเมื่อวาน

กล่าวคือ ใช้ **"วันเริ่มกะ" (work date)** เป็นเกณฑ์ ไม่ใช่เที่ยงคืนตามปฏิทิน
และนำ `work date` ไปใช้เป็น `DailyChecksheet.date` เพื่อให้ doc ของกะ N ที่ข้ามวัน
อยู่ตรงกับวันเริ่มกะที่ถูกต้อง

## 7. Logic ที่จะใช้ (2 conditions)

ระบบรู้อยู่แล้วว่าตอนนี้เป็นกะอะไรผ่าน `GetCurrentShiftUseCase.getShiftByTime()`:
- 22:00 – 05:59 → กะ N (กลางคืน)
- 06:00 – 13:59 → กะ M (เช้า)
- 14:00 – 21:59 → กะ E (บ่าย)

**ข้อสังเกต:** ช่วงหลังเที่ยงคืน 00:00–05:59 **ต้องเป็นกะ N เสมอ** (เพราะ 06:00 เป็นขอบของกะ M)
ฉะนั้นการเช็ค `hour < 6` ก็เพียงพอ ไม่จำเป็นต้องผูกกับ `getShiftByTime()` ซ้ำ

```kotlin
fun getWorkDate(now: LocalDateTime): LocalDate =
    if (now.hour < 6) {          // 00:00 – 05:59 (หลังเที่ยงคืน, อยู่ในกะ N)
        now.toLocalDate().minusDays(1)   // → เป็นของ "เมื่อวาน" (วันเริ่มกะ)
    } else {
        now.toLocalDate()                 // → เป็นของ "วันปัจจุบัน"
    }
```

### ตารางผลลัพธ์ตามเวลา

| เวลาจริง     | getShiftByTime | hour < 6? | วันทำงาน (work date) |
|--------------|----------------|-----------|----------------------|
| กะ N 23:30   | N              | ❌        | 02 (วันเริ่มกะ) ✅    |
| กะ N 00:30   | N              | ✅        | 02 (ย้อนเป็นเมื่อวาน) ✅ |
| กะ N 05:59   | N              | ✅        | 02 (ย้อนเป็นเมื่อวาน) ✅ |
| กะ M 06:30   | M              | ❌        | 03 (วันปัจจุบัน) ✅    |

ดังนั้น **ทั้ง 8 ชั่วโมงของกะ N จะรวมเป็น "วันเริ่มกะ" (02) เดียว** ทั้งหมด ✅

## 8. สิ่งที่จะต้องเปลี่ยนในโค้ด

### 8.1 เพิ่ม helper กลางใน `DateUtils`
เพิ่มฟังก์ชันกลางสำหรับ "วันทำงาน" เพื่อให้ทุกจุดใช้ค่าเดียวกัน:

```kotlin
/** work date — ก่อน 06:00 น.ให้ย้อนเป็นวันก่อนหน้า (รองรับกะข้ามวัน) */
fun getWorkDate(now: LocalDateTime = LocalDateTime.now()): LocalDate =
    if (now.hour < 6) now.toLocalDate().minusDays(1) else now.toLocalDate()

/** รูปแบบ work date แบบ yyyy-MM-dd (ใช้เป็น key) */
fun getWorkDateString(now: LocalDateTime = LocalDateTime.now()): String =
    getWorkDate(now).format(dbFormat)
```

> ⚠️ ต้องระวัง: `getTodayString()` ปัจจุบันถูกใช้เป็น key ของ "ตรวจแล้ว"
> เรา**ไม่ควร**เปลี่ยน `getTodayString()` ทุกจุดโดยไม่กลั่นกรอง เพราะบางจุดอาจต้องการ "วันปฏิทิน"
> ควรเพิ่มฟังก์ชันใหม่ `getWorkDate*()` แล้วย้ายเฉพาะจุดที่เป็น "วันตรวจ/วันทำงานกะ" ไปใช้

### 8.2 จุดที่ควรเปลี่ยนเป็น `getWorkDate()` / `getWorkDateString()`
จุดที่เกี่ยวกับ **"วันทำงาน/วันตรวจ/วันเริ่มกะ"**:

| ไฟล์ / จุด | ปัจจุบันใช้ | ควรเปลี่ยนเป็น | เหตุผล |
|-----------|-----------|---------------|--------|
| `MainActivity` — `todayStr` (key ของ `checkedVehicleStore` + `remember`) | `DateUtils.getTodayString()` | `getWorkDateString()` | ตรวจแล้วแยกตามวันเริ่มกะ ไม่หายหลังเที่ยงคืน |
| `CheckedVehicleStore` — key ในบันทึก | รับ `date` จาก caller | ใช้ `work date` ที่ส่งมา | เพื่อให้ข้อมูลตรวจรวมกันวันเดียว (สมมุติ caller ส่ง work date) |
| `DailyChecksheet`/`submitChecksheet` — ฟิลด์ `date` | `LocalDate.now()` | `getWorkDate()` | วันที่บันทึกตรงกับวันเริ่มกะของกะ N |
| เอกสาร/รายงานอื่น ๆ ที่ต้องการ "วันทำงาน" | `getTodayString()` | `getWorkDateString()` | ให้รายงานเรียงตามกะจริง |

> 📌 จุดที่**คงไว้**เป็นวันปฏิทิน (`getTodayString()` ตามเดิม):
> ตัวอย่าง เช่น การแสดง "วันนี้" แบบทั่วไปที่เป็นปฏิทินจริงโดยแท้ (ถ้ามี)
> ต้องพิจารณาเป็นกรณีไป

### 8.3 ตรวจสอบการเรียก `LocalDate.now()` / `getTodayString()` ทั้งหมด
ก่อนแก้ต้องหาจุดใช้ที่ครบทุกจุด เพื่อไม่ให้พลาด เช่น:

```bash
grep -rn "getTodayString()" app/src/main/java
grep -rn "LocalDate.now()" app/src/main/java
```

## 9. ผลลัพธ์ที่คาดหวังหลังแก้

1. Operator กะดึกที่ตรวจข้ามวัน (หลังเที่ยงคืน) **เห็นรถที่ตรวจแล้วก่อนเที่ยงคืนอยู่ครบ** ไม่ถูก reset เป็น "รอตรวจ" ใหม่
2. การนับ "ตรวจครบแล้วทุกคัน" ต่อเนื่องข้ามเที่ยงคืน
3. `DailyChecksheet` บันทึก `date` ตรงกับ **วันเริ่มกะ** ทำให้รายงาน/ข้อมูลเรียงตามกะถูกต้อง
4. ทั้ง 8 ชั่วโมงของกะ N ตกเป็นวันทำงานเดียวกัน (วันเริ่มกะ)
5. **แยก doc ต่อกะ** + `main_remark` เป็นตัวบอกเหตุการณ์ → ระบุได้ว่ากะไหนเกิดเหตุ / ผู้พบ/ผู้ทำ → หัวหน้าไล่บี้ได้
